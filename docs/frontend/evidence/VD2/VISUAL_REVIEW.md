# VD2 rendered review ledger

Compared the accepted VD1 captures in `../VD1-R2/visual-full/` with the final VD2 screenshots in `screenshots/`, and checked the owner-directed source of truth and `DESIGN.md`. No separately identified approved Figma frame was provided for pixel comparison. These are local Chromium renders with synthetic or unavailable backend state, not live integration proof or independent acceptance.

| Surface | VD1 reference and contract | Final VD2 render and decision |
| --- | --- | --- |
| Desktop rail | VD1 `desktop-shell.png` had a 248px graphite rail with one long list. The design contract requires route hierarchy and an active gate marker. | `desktop-overview.png` retains the measured 248px rail, groups all 29 product destinations, and preserves the left marker/background active state. The rail scrolls independently; no route was removed. |
| Command and context bar | VD1 had workspace, command discovery, last read, and account; the narrow capture hid account context. | `desktop-overview.png` and `narrow-overview.png` retain all four. The last-read label says “not checked” until a read occurs. At 360px the account remains visible; at 200% the container rule stacks it for readable reflow. |
| Authority Strip | VD1 page-level boundary copy did not enumerate authority classes. The source of truth requires Read, Write, Execution, and Destructive without implying grants. | The shell-wide strip names all four classes, states “Classification only”, and shows principal uncertainty. Text carries meaning; the destructive border is secondary. `forced-colors-overview.png` retains separations. Existing page-level boundary copy remains specific to its route. |
| Trust ribbon | VD1 overview had no Client → Gateway → Executor orientation surface. `DESIGN.md` requires a status-bearing trust path. | `desktop-overview.png` and `narrow-overview.png` show all three stages. Copy distinguishes browser request intent, gateway authorization, and server-mediated execution; gateway and executor live status remain unverified/unknown. |
| Degraded state and job semantics | VD1 route panels named unavailable/forbidden states; completed work must not read as applied. | `degraded-overview.png` shows last-read context without repeating panel text or implying global service health. The shell footer explicitly says completed does not mean applied. Existing job lifecycle behavior was not changed. |
| Palette, density, and contrast | Graphite/mineral/Delft and IBM Plex are normative. Static cards have no decorative shadow. | `desktop-overview.png`, `dark-delft-overview.png`, `warm-workbench-1280.png`, and `warm-workbench-360.png` retain the approved token family. Shell support text over Warm Workbench is 5.6702:1 by the recorded sRGB calculation; axe found no violations in tested states. |
| Drawer, keyboard, and zoom | VD1 had one app-owned drawer with Escape and focus restoration. At narrow widths the viewport must not overflow. | `narrow-drawer.png` shows the same drawer owner and grouped links. Browser interaction tested Escape, route navigation, focus restoration, forced colors, reduced motion, and 200% reflow. `zoom-200-narrow.png` is tall but its required controls remain readable and reachable without horizontal overflow. |

The first full VD2 browser run exposed duplicate exact error copy and zoom overflow. The banner copy was made shell-specific and moved into a labeled region; container-width reflow fixed the overflow. The subsequent full run passed 75/75. No route panel deep redesign or VD3 work was performed.
